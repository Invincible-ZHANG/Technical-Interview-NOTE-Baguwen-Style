1/60 秒 ≈ 16.7 ms。这是手机在室内最常用的快门速度之一，也是整条成像链路的**时间预算**。

我平时的工作就是保证这十六毫秒里，每一步都别掉链子。这篇把它拆开写一遍——知道这个流程之后，很多拍摄时的"怪现象"会突然变得理所当然。

## 一、光变成电子

传感器每个像素底下是一个光电二极管。光子打进来，激发电子，转换效率叫**量子效率（QE）**，好的背照式传感器能到 70% 以上。

电子被收集在势阱里，能装多少叫**满阱容量（FWC）**。这就是为什么高光会"过曝"——势阱满了，再多的光也装不下，数值被钉死在同一处，信息就永久丢了。

曝光时间决定了积累多久。手机没有机械快门，靠**电子快门**：清空势阱、等一段时间、读出。这个"等一段时间"，就是你在参数里看到的 1/60。

## 二、读出：为什么会有果冻和条纹

关键点在这里：**一整块传感器不是同时读出的，是一行一行读的。**

因为 ADC 数量有限，逐行读是最经济的做法。这就带来了**卷帘快门（rolling shutter）**。

假设 12MP 传感器有 3000 行，整帧读出要 20 ms，那么第一行和最后一行在时间上差了 20 ms。如果这期间物体在动：

- 拍旋转的风扇 → 扇叶是弯的
- 拍快速横穿画面的车 → 车身被拉斜
- 拍手持夜景 → 帧内抖动导致部分区域糊、部分清晰

而这个 20 ms 的读出时间还有个副作用：**闪光灯同步极限**。机械快门时代叫 x-sync，电子快门也一样——快门速度比读出时间快，闪光只在其中一小段被某些行捕捉到，剩下的行就是黑的。

**为什么路灯下拍照会出现明暗条纹（banding）？**

因为人造光源不是连续发光。50 Hz 交流电下，灯具亮度以 100 Hz 周期波动，一个周期 10 ms。如果曝光时间是 10 ms 的整数倍（1/100 s、1/50 s），每行积累到的亮度一致，条纹消失；如果卡在中间（比如 1/120 s），不同行落在亮度波形的不同位置，就会出现横条纹。

这解释了那条老经验：**在国内拍室内，优先用 1/100 s 或 1/50 s**。现在很多 LED 用高频 PWM 调光（几 kHz），条纹会变得很细甚至看不出来，但慢动作视频里依然躲不掉。

## 三、模拟前端与 ADC

读出的是电荷，要先转成电压、再放大。**模拟增益**就是这里的放大倍数，对应你调的 ISO。

放大是有代价的：信号放大的同时，读出噪声也一起放大。所以"高 ISO 噪点多"不是算法问题，是**进 ADC 之前信噪比就已经定了**。

ADC 把电压量化成数字，手机常见 10 bit 或 12 bit。12 bit 意味着 4096 级亮度——这就是 RAW 文件能记录更多层次的原因。JPEG 只有 8 bit（256 级），中间那部分层次是 ISP 用曲线压出来的。

## 四、MIPI：把数据搬出去

12MP × 12 bit × 30 fps ≈ 5.4 Gbps。这个量级没法用普通并行接口传，所以用 **MIPI CSI-2** 差分串行链路，通常 2~4 条 lane。

在驱动侧，这一层最常出问题的地方是**带宽和时序**：lane 数不够就掉帧，时序配错就花屏，电源管理没做好就是打开相机黑一下。用户看到的是"相机打开慢""预览卡"，底下全是这些参数。

## 五、ISP：一帧画在这里被"发明"出来

进入 ISP 之后，图像处理流水线大概是这样：

```
BLC（黑电平） → LSC（镜头阴影） → DPC（坏点）
  → 去马赛克（Demosaic） → 白平衡 → CCM（色彩矩阵）
  → Gamma → 转 YUV → 降噪 / 锐化 → 编码或显示
```

几个值得单独说的：

**去马赛克**。传感器每个像素只感知 R、G、B 中的一种（Bayer 阵列），有 2/3 的颜色是**猜出来的**。猜的方法决定了摩尔纹和伪色。拍密集的织物、远处楼房的空调外机，容易出现彩色波纹，就是这里没猜好。

**G 通道为什么是 R、B 的两倍？** 因为人眼对绿色最敏感，亮度信息主要来自绿光。牺牲色彩分辨率换亮度分辨率，是一笔划算的交易。

**CCM（色彩校正矩阵）**。传感器的三原色响应和人眼不一样，得用一个 3×3 矩阵把它"掰"回接近人眼。这个矩阵没有唯一解——**不同厂商的色彩风格，相当大一部分就来自这个矩阵的选择**。所谓"这家的肤色好看"，本质是矩阵参数调得讨喜。

**Gamma**。人眼对暗部变化更敏感，所以要用一条非线性曲线把有限的 8 bit 分配到感知上更重要的地方。这也是为什么 RAW 直接转 JPEG 会显得灰——它还没上曲线。

## 六、为什么这些知识对拍照有用

不是为了炫技，是因为它解释了一批实际现象：

| 你遇到的现象 | 硬件层的解释 |
|---|---|
| 室内灯光下照片有横条纹 | 曝光时间与光源频率不匹配 |
| 拍快速运动的物体变形 | 卷帘快门，行间有时差 |
| 高光死白拉不回来 | 势阱满了，超出量程的信息不存在 |
| 手机开相机慢 | 传感器上电、MIPI 链路建立、AE/AWB 收敛 |
| 夜景边缘比中心糊 | LSC 后边缘信噪比更差 |
| 同一场景不同手机色彩风格差异大 | CCM 与 Tone Mapping 的策略不同 |

## 七、一点感受

写驱动的时候，相机是一堆寄存器、时序图和错误码。拍照的时候它是光和情绪。

但这两种视角其实是同一件事的两端：**十六毫秒里发生的一切，决定了你能不能留住那一刻**。知道势阱会满，所以宁欠勿过；知道卷帘有延迟，所以拍运动要预判；知道光源会闪，所以室内锁 1/100。

技术不会让照片变好看，但它能让你少浪费几次快门。
